# 本地录音阶段测试与 vivo 验收

测试结构：纯业务 JUnit4 单元测试；Room 仪器测试使用内存 SQLite；Compose 仪器测试覆盖导航恢复、尺寸矩阵和大字体；真实平台 MediaRecorder 服务测试覆盖自动启动、重复启动、Activity 重建、暂停／继续、后台保存及真实 M4A 校验。Hilt 管理生产依赖，业务和数据库测试直接构造依赖。

AI 配置增加 JSON 校验与合并、协议／能力区分、密钥 AES-GCM 和实际 Keystore 测试。MockWebServer 4.12.0 与 okhttp-tls 4.12.0 仅供仪器测试：运行本机 HTTPS 假服务，分别验证模型列表、Responses 和 Chat Completions 的请求／响应、重定向、鉴权错误、取消与证书校验；生产代码继续使用平台 HttpsURLConnection，不包含测试证书或信任例外。UI 覆盖 DeepSeek／豆包预设、独立语音模型、删除解绑、未保存草稿、真实 Activity 重建、窄窗和大字体。

测试源码在 `app/src/test` 和 `app/src/androidTest`。测试报告分别位于 `app/build/reports/tests/testDebugUnitTest`、`app/build/reports/androidTests/connected/debug`。Room 结构导出到 `app/schemas`；禁止破坏性自动迁移。

Compose 尺寸截图由仪器测试生成：400 / 610 / 900 dp 宽 × 400 / 500 / 1000 dp 高，并追加 1.5 倍字号。测试设备实际可绘制范围可能小于请求尺寸；截图用于人工检查，不宣称已建立像素回归基线。设备截图目录为应用 external files 下的 `screenshots`。本阶段使用真实设备截图，未引入已弃用的旧 Compose Preview screenshot Gradle 插件或预览 AGP。

Detekt 聚焦协程、危险空值／类型转换、不可达代码、异常吞没与通配符导入；ktlint 管理格式。Jacoco 已应用，当前不以覆盖率百分比代替录音链路验收。

## vivo 手机验证

1. 安装 `app-debug.apk`，打开「随声记」，点击开始并允许麦克风。录一段约 15 秒语音，暂停 5 秒再继续，停止后核对录音库和播放。播放时拖动进度，暂停并恢复。
2. 开启录音通知；在桌面添加「随声记」小组件，关闭应用后点击小组件。允许必要授权后应自动录音，不需再次点开始。重复点击启动入口不应新建会话；点击小组件或通知的停止保存，回到录音库核对只有一条录音。
3. 录同一段时反复展开／合拢、横竖屏、分屏、返回桌面及息屏，建议连续 30 分钟。检查计时继续、通知正常、同一条记录、无重复录音，回放检查切换点是否断音。按实际 OriginOS 版本核对后台与电池限制，不预设系统菜单位置。
4. 小组件分别缩小和放大；紧凑尺寸保留开始／停止，较大尺寸增加暂停／继续。关闭通知权限后，页面应给出小组件停止说明；录音仍能从页面或小组件停止。
5. 拒绝麦克风权限：不得出现虚假的录音中状态；重试或系统设置授权后再录。录音过程中关闭系统麦克风开关、打开其他录音应用或接听来电，观察受限／错误提示并检查已保存内容。特定设备未报告系统静音时，音量为零只作视觉反馈，不把安静环境误判为故障。
6. 在有测试录音时强制停止应用，再次打开：旧会话应显示意外中断，不能自动开启麦克风。未封装完的单个 M4A 可能无法播放，应用应明确说明并保留临时文件；先前正常保存的文件必须仍可播放。
7. 在外屏、内屏、窄分屏、系统 1.5 倍字号和浅／深色下检查主要操作及列表详情。宽窗双栏、窄窗单栏；选中条目应保留，系统返回正常。

不要卸载或清除数据来测试升级，否则私有录音会被删除。手机尚未连接时，声音质量、vivo 后台限制、实体折叠连续性和启动速度只能列为待真机验收。

实际执行结果将记在 `docs/first-recording-delivery.md`。

## 0.2.0 配置与 UI 的 vivo 验收

1. 覆盖安装新 APK，保留原有应用数据；核对旧录音能播放。首页打开设置，添加多个 provider，例如 DeepSeek 和豆包语音；连接名称尽量区别明确。
2. DeepSeek 预设应为 Responses，Base URL 为 `https://api.deepseek.com`。在标题／总结中选择该 provider 和 `deepseek-flash` 或 `deepseek-v4-pro`，保存自定义提示词和推理强度。重新打开、强制停止后再打开，已保存值应保留，密钥不回显。默认不会联网。
3. 可以主动检查模型列表；需要更明确的协议验证时在文本能力中点击“测试文本模型”，确认后只发送固定检查文字，会消耗少量 token。错误密钥应显示鉴权失败；无法解析、证书错误、返回未完成或不兼容 JSON 不能显示测试成功。无 `/models` 的自定义服务可直接填模型并测试文本接口。
4. 为语音转写独立选择支持转写的 OpenAI 兼容连接和模型，或豆包语音连接、`bigmodel` 与语音 Resource ID。DeepSeek 文本预设不出现在语音连接选项中。豆包仅显示 API Key，不显示旧版鉴权和配置测试入口；保存时校验本地格式。本阶段不上传音频，也不承诺当前 M4A 已被豆包接口识别。
5. 编辑连接／提示词时展开、合拢、分屏，检查草稿和当前页面保留；外屏键盘弹出后输入框可滚动到可见位置，顶部保存可点击。未保存返回应提供继续编辑／放弃选择。进程被系统终止后未保存草稿不承诺恢复，密钥不会进入系统保存状态。
6. 录音中打开设置并编辑，多次折叠；录音状态、暂停及停止按钮应始终可达，停止后只有一条新录音，音频可播放。依旧执行前述 30 分钟后台录音验收。
7. 切换浅色、深色、系统跟随及动态取色；验证大字体下文本、按钮、开关和系统栏可辨认。模拟器截图用于参考，请在 vivo 内外屏实际检查视觉布局。
8. 用系统文件选择器导出 JSON，检查文件没有 API Key／Access Token；重新导入前应显示合并预览，取消不改变配置。已有同 ID 的连接、密钥、已编辑能力与提示词应保留；新增连接需重填密钥。删除连接会清除凭据并解除绑定，录音保留。

本阶段结果与协议文档来源见 `docs/ui-ai-configuration-delivery.md`。
