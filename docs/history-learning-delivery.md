# 历史检索与可靠学习交付

日期：2026-10-10；版本：0.4.5（versionCode 12）。

## 使用入口与实际范围

录音库的「历史与录音检索」或助手菜单进入同一个页面。关键词、ISO 起止日期及项目名组合筛选本机聊天原文、助手回复、人工修订转写和机器转写。日期包含起止当天，按来源发生时的时区计算；项目按事实关联范围或原文中的字面项目名匹配。机器转写明确标注，不能当作已确认原文。结果最多 10 条，每条最多 300 字，优先完整短语、匹配词数量，再按时间排序；打开来源时重新校验版本。

查询直接读取现有事件和投影，不复制私人正文，不联网，不使用 Embedding，也没有新建持久化全文索引。中文按二元字匹配，不能保证自然语言语义检索；大规模历史的性能仍需实测。

「最近学习」展示最近 50 项记忆及整理任务变更：新增／补充／替代／澄清、当前审核状态、新旧正文、证据、来源入口、所用模型和失败原因。已忘记、失效、合并清理的正文不从历史事件恢复。可以进入记忆审核或取消尚未完成的聊天整理任务。

## 来源与忘记

不可变 contentId 是来源版本。查询、按 ID 读取、工具回执、回复和记忆结果提交都重新校验当前来源；人工修订转写会清理旧正文和依赖旧版本的回复。

忘记／失效事件在清除正文前保留最小来源 ID。原先被撤回的版本继续屏蔽，包括重新学习后；活跃结构化遗忘范围还按已知谓词别名与项目字面范围保守屏蔽整条来源及关联回复。例如咖啡范围包含拿铁等已知别名。屏蔽可能让同条消息的无关部分也不可检索；不是任意同义改写或任意主题的语义删除。已发给 provider 的内容无法通过本机忘记撤回。

## 授权队列与费用边界

检索本身不会整理或上传。用户可以选择 1–10 条已完成的聊天原文，在独立对话框核对 MEMORY 服务及最多调用数后授权排队。重复选择有既有整理记录的来源不会再次调用，包括失败／取消记录；确需重试时进入原对话明确触发新的手动尝试。录音记忆提取继续使用录音详情和原有 AI 队列，本次历史批次不批量上传录音。

MemoryPlanning 的 REQUESTED 投影是持久化 outbox；业务事务提交后才用 WorkManager 唤醒。历史批次和启动恢复等待网络连接。重放只重建投影，不联网或入队；应用启动单独恢复。每条任务固定 MEMORY 连接、模型、提示词、来源与记忆版本，执行前复核，连接变更不会暗换服务。

每个任务最多 1 次 provider 调用、来源最多 4,000 字、最多 10 条相关记忆、最多 3 项计划；尝试最长 120 秒，现有文本网关输出上限 4,096 tokens。自动整理默认关闭，只处理开启后新完成的聊天，每个 UTC 日最多 20 次 STARTED，失败及后来被删除的输入仍计入。历史批次的授权最多 10 次，手动重试是另一次明确授权；每日 20 次上限不代表所有手动请求的全局上限。

RUNNING 在进程恢复时标为中断，不自动重试未知计费结果；REQUESTED 可恢复。来源变化、授权关闭、取消或预算到达使任务终止；迟到响应不能写回。后台 Worker 停止时，已开始的尝试由进程协程持有，可能继续完成，数据库 RUNNING 状态防止另一个 Worker 重复开始；进程丢失则走中断规则。系统可能延迟后台唤醒，不能承诺及时整理。

这里控制调用次数、输入／输出规模和尝试时间，没有硬性货币预算或真实费用计量。实际费用由服务计价，网络中断、超时、取消仍可能已产生费用，反馈明确提示用户决定是否重试。

## 可选自动确认

设置 → 助手 → 记忆方式新增默认关闭的自动确认。只允许有限白名单中的完整、直接普通中文偏好／项目单句，要求原文、证据和正文逐字一致、self、显式 ADD，无日期或目标。敏感信息、引用、假设、其他主体、多句、冲突、替代及不在白名单内的事实仍待审核。自动确认开关与自动整理独立；开启前需配置 MEMORY 模型，提交前按最新授权检查。

45 个非私人合成规则样例：误记 0、漏记 3、错误覆盖 0，普通事实自动保存召回 8/11（72.7%）。另有 30 条独立合成来源的导出与离线捕获响应评分器，使用生产 schemaVersion 2 解析器；导出和人工响应评分路径均已实际执行。这是规则／人工夹具结果，没有真实 provider 调用，不能作为真实模型准确率。复现命令及定义见 [质量评估](memory-quality-evaluation.md)。
