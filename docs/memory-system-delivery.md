# 记忆系统第一版：独立候选整理

日期：2026-10-10。版本：0.4.1（versionCode 8），数据库版本 4。此版开始落实 [个人助理架构](architecture/personal-agent.md) 的记忆核心，不代表 A–D 全部完成。

后续 0.4.2 的派生回复清理、取消、超时与检索加固见 [复审记录](memory-system-review.md)。本文保留第一版交付范围及当时验证结果。

## 使用

1. 设置 → 模型与能力，分别配置「私人助手」与「记忆提取」的连接、模型和提示词。两者可以使用不同模型；不会用 ANSWER 代付 MEMORY 调用。
2. 正常聊天。回复完成后点「整理记忆」，页面说明所选记忆服务、文本范围和调用费用，确认后执行一次请求。只发送本条用户消息和至多 10 条相关已确认记忆；不发送助手刚给出的建议。
3. 有原文依据的新事实成为「待确认」卡片，显示证据。确认成功后才进入后续对话；没有新候选也显示实际整理结果。可以停止，失败／中断后手动重试。
4. 消息中的「记住…」继续支持人工编辑并主动保存，不依赖记忆模型。聊天未配置 MEMORY 时仍可用。
5. 对话操作 →「已确认记忆概览」，按偏好与约定、项目与待办、其他事实显示已确认内容；点「管理记忆」可纠正或忘记。

聊天请求只保存回复，不再采用 ANSWER 输出附带的记忆候选。仍兼容旧 JSON 回复正文，旧候选、ID、来源、确认状态和忘记指纹保留。

## 实现与持久化

- `MemoryPlanner` 独立使用 MEMORY 配置，固定连接／模型／提示词、来源正文 ID、关联记忆版本和全局知识修订。API Key 只从加密设置读取，不进入任务快照、事件或日志。任务由进程级作用域持有，Activity 重建不重发；整理串行执行，单次时限 120 秒。
- 输出是严格的版本 1 ADD／IGNORE 计划，最多 3 项。ADD 的类别、长度和逐字证据必须有效；格式错误或任一证据不符，整次结果不提交。模型仅提出候选，不能直接确认、合并、替代或删除。
- `MemoryPlanningRequested / Started / Completed / Failed / Cancelled` 与任务 Room 投影同事务提交；新增候选和整理完成状态同事务提交。重复启动复用在途任务，已完成消息不再次收费；失败重试生成新任务。
- 请求快照存入可删除 `contents`，事件仅保留引用与状态。忘记、纠正、确认、来源删除等操作保守地使在途快照失效；上传前与候选提交前再次检查知识修订、来源正文和引用版本。删除／忘记会清除相关整理快照；状态变化触发协程取消，迟到响应不能发布候选。
- 同一用户消息已有忘记／失效的记忆时拒绝重新整理，需明确人工「记住…」。普通重复提取继续服从既有正文指纹抑制。
- 转写人工修订会失效依赖旧版本的记忆并清理记忆历史正文。删除对话取消其整理任务并清理输入快照；候选与已确认事实沿用已有删除路径。
- 重建只消费事件和保留正文，不持有网络／调度器，也不把整理任务写入 outbox。进程恢复将未完成整理标为 INTERRUPTED，用户重试前不再次上传。
- 已确认文本事实形成确定性概览。聊天先做中文二元字匹配与类别匹配，再补充至多 8 条偏好／约定；总量最多 24 条、6,000 字符预算。其他不相关事实不填满上下文，无 Embedding。

Room 3→4 仅增加 `memory_planning`，没有破坏性迁移；旧记忆不补造主体、谓词、时间或确认状态。

## 后续边界

此版保留文本事实模型：没有结构化 subject／predicate／scope／有效时间，没有多来源依赖图、自动替代、同义合并、时间线或会话摘要。概览的分类表示内容类别，不保证人物事实属于用户本人，也不自动推断经历；模型主体、相对日期、敏感内容和临时状态判断仍需用户审核。

全局知识修订保护较保守，无关记忆的变更也可能中断整理。已确认偏好的小型常驻上下文尚未区分用户主体，来源语义依赖正文；后续结构化事实层需消除此限制。

同来源和完全相同正文防重学已覆盖；跨新消息的同义表达仍可能重新形成候选。主体／谓词／主题级抑制尚未实现，不能宣称完成架构中的语义忘记。上传至 provider 的既有内容无法由本机删除收回。

SOUL／内置 skills、原生工具循环、主动来源查询、自动记忆开关和后台整理仍未接入。本版每次整理均由用户主动触发。下一步优先做结构化来源与主体、冲突／替代计划、多来源与忘记抑制，再接入工具主动回忆与持续整理。

尚未完成真实模型长期质量集、误记／漏记／召回／成本评估与 vivo 实体折叠连续性验收；假服务格式测试不能证明模型理解质量。
