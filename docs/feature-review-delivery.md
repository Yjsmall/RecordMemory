## 已修正的问题

| 问题 | 修正与验证 |
| --- | --- |
| 记忆类别字段 `type` 与事件 JSON 类型判别字段冲突，候选无法入库 | 类别序列化为 `memoryKind`，事件类型字段继续使用 `type`；真实 Room 测试覆盖候选生成、编辑、忘记、删除和回放 |
| 已取消任务及旧尝试的网络返回可写入当前投影 | 完成／失败前核对 RUNNING 状态和当前 attempt；过期结果不追加事件、不覆盖新结果 |
| 人工校正原文后，在途转写仍可覆盖校正 | 原文保存同事务取消 ASR 和相关整理任务，迟到返回不再写入；回放保持校正结果 |
| 前台调度与 WorkManager 可同时执行同一批队列 | 同进程 drain 用 Mutex 串行执行；租约包含音频转换和网络超时；失败重试时间以实际完成时间计算 |
| WorkManager 遇到暂未到重试时间的队列会误判全部完成，留下无人唤醒的任务 | 只要 outbox 仍有待处理项，后台 worker 保持 retry；异常也不再当成任务全部成功 |
| 删除／忘记只删除当前正文，早期版本仍留在 contents 中 | 同事务清理事件引用的历史正文；记忆任务不再重复存储候选正文，旧冗余结果一并清理；删除后回放不恢复正文 |
| 音频转换超时后可能上传已截断 WAV | 必须解码到 EOS 才发布临时 WAV；超时明确失败，M4A 原档保留 |
| 详情页编辑／AI 操作错误只显示在录音列表 | 全局 Snackbar 反馈错误；录音自身错误继续显示在详情 |

## 原子岛

原实现缺少专用通知标签，使用未核实的 SOUND_RECORDER 场景，更新 operation 与内容字段也不完整。现在使用独立 tagged 通知、TIMER 场景、按钮模板及完整卡片／岛内容，创建与更新均使用 operation 0，revision 递增，结束发送 operation 2 并取消通知。录音刷新切回主线程，避免结束后音频线程重新发布通知。

只向 vivo／iQOO 尝试注册本应用场景，不使用其他应用包名，不绕过 ROM 检查。原子岛按钮为暂停／继续与停止保存，点击内容打开应用；移除了录音中直接删除按钮。标准麦克风前台通知独立保留，暂停时计时冻结，结束移除通知。

字段核对参考：[origin-isle 社区资料](https://github.com/fvhde/origin-isle)。这是社区逆向资料，**不是 vivo 官方接口文档**；未引入该库或复制其源码。标准 Android 模拟器只能验证通知序列化、按钮实际控制服务与通知生命周期，不能验证 OriginOS 显示。ROM 是否允许本包使用场景、原子岛是否完整呈现，仍需 vivo 真机验收。

## vivo 验收

1. 覆盖安装新 APK，不卸载或清除数据。先核对原有录音播放及已存 provider／模型配置。
2. 允许录音通知，确认 OriginOS 对该应用的原子岛／通知功能已开启（具体入口随 ROM 版本变化）。从应用或桌面小组件开始录音，返回桌面，检查岛内显示图标、计时、录音状态，展开卡片应有暂停和停止保存。
3. 暂停约 5 秒：状态改为已暂停、计时冻结、按钮改为继续；继续后计时增长。点击岛内容应回应用。停止保存后岛与普通录音通知消失，只有一条录音，回放能听到暂停前后内容。
4. 同一段录音中反复展开／合拢手机、切横竖屏、分屏和息屏，检查会话与计时继续，结束后只有一条录音；长时间后台和声音质量仍按 `docs/testing.md` 的 30 分钟步骤验收。
5. 若原子岛仍不显示或为空白，先用普通录音通知验证暂停／继续／停止能正常工作，并记录机型、OriginOS 完整版本和从哪个入口开始录音。这个结果用于判断 ROM 场景授权或模板差异，不能用模拟器测试代替。
6. 使用一段可上传的测试录音，在详情原文页手动转写；确认成功后生成标题／总结／记忆。检查候选确认、编辑、查看依据、回到原录音和忘记；修改原文后重新生成，人工标题／总结的模型结果应作为建议等待采用。
7. 在外屏、内屏、大字体及深色下检查三页签、记忆菜单、编辑键盘与保存按钮；返回未保存编辑应提供继续／放弃选择。删除测试录音后关联正文和来源记忆不应重新出现。
