# 私人助手与对话记忆 · 0.4.0

此前的记忆功能已经支持从录音文本提出候选，以及确认、编辑、合并、禁用、忘记和查看来源；尚未用于持续对话。本版增加首页「私人助手」，将已确认记忆用于对话，让偏好、项目、约定和计划跨会话保留。它通过本地记录与请求上下文实现个性化，不训练模型，不使用 Embedding。

## 使用

1. 设置 → 模型与能力 → 私人助手：选择已有文本 provider，填写模型并保存。语音转写、标题、总结、记忆提取继续独立配置。
2. 首页打开「私人助手」。首次可聊聊自己的偏好、正在做的事，也可以直接提问。
3. 回复下面的「可以记住」卡片只有确认后才成为长期个人记忆；忽略会移除候选正文。用户消息中的「记住…」可编辑文字、选择类别并主动保存。
4. 顶部记忆入口可查看、编辑、禁用或忘记。来源按钮可以回到原对话。为保证来源删除完整，合并限定在同一录音或同一对话内。
5. 右上角菜单可新建、切换历史对话、调整对话模型或删除当前对话。删除会清理全部尝试的用户正文、回复、提示词及来源记忆；其他来源保留。

## 上下文与控制

- 只将已确认记忆作为长期上下文，最多 24 条／约 6000 字预算，按简单文本匹配与偏好／约定优先排序。历史最多 12 个完整轮次／24000 字；单条输入最多 4000 字。并非每次发送全部记忆，不是无限上下文，也尚未加入录音全文检索工具。
- 每次只调用一次所选模型，使用正规的 user／assistant 消息。Responses 使用 `input` 消息数组，Chat Completions 使用 `messages`；均请求 `store=false`，不依赖远端 conversation ID。服务仍会接收被发送的内容，其日志和保留策略由该服务决定。
- 同次回复可提出最多三条候选。候选必须附本轮用户消息中的逐字证据；不会从助手回复自动提取个人事实。普通文本服务回复可以显示，但不会生成候选。用户仍需判断候选是否准确。
- 记忆纠正、禁用或忘记后，后续请求会跳过相关来源轮次及使用过期记忆的历史轮次，防止通过历史再次引入旧信息。在途请求会复核记忆版本；不再有效的结果不会发布。已经发给服务的请求无法撤回。
- 网络错误、停止回复、进程中断均需手动重试；应用重开不会自动续发对话。Activity 重建、折叠及打开其他页面不会重复发送。录音仍由独立前台服务拥有，助手页保留暂停和停止入口。
- 会话、请求、尝试、回复、取消、删除与记忆变更共用事件日志；正文在可删除的 contents 表。Room 2 → 3 增量迁移保留录音及旧记忆。回放只更新投影，不调用模型、不重开录音、不创建 outbox 工作。

## vivo 验收

覆盖安装 0.4.0，不清除数据。先核对原录音、转写与已确认记忆保留。

1. 配置私人助手模型，发送「我喜欢简洁的回答，周末通常想安静地休息」。核对回复显示、候选待确认；确认后新建对话，询问「根据我的偏好，给我一个周末建议」。
2. 点击「记住…」保存一条项目偏好，进入记忆页检查来源、编辑和忘记。忘记后再问相关问题，检查助手不再依据旧记忆作答；原聊天记录仍可查看。
3. 回复中停止、断网、切换页面、展开／合拢、分屏与键盘输入，核对只有一次请求、草稿保留、发送按钮可达。强制停止后重开，未完成回复应显示中断，需手动重试。
4. 录音期间进入助手聊天并多次折叠，检查暂停／停止入口和录音连续性。
5. 删除一段带记忆的对话，核对历史会话与来源记忆消失，其他来源仍保留。已经传给 provider 的内容不会因本地删除而自动从服务端删除。
