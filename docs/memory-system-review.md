# 记忆系统复审与加固

日期：2026-10-10。版本：0.4.2（versionCode 9），数据库仍为版本 4。复审基线为 0.4.1 的独立候选整理。本轮集中修复删除完整性与运行反馈，不扩展自动记忆或工具权限。

## 问题与修复

| 级别 | 可复现问题 | 修复后的行为 |
| --- | --- | --- |
| 高 | 忘记卡片只清理记忆正文；用过它的回复和旧尝试快照仍存于本机，虽然已被后续检索排除 | 沿记忆引用、来源消息与历史会话依赖计算受影响回复，清理所有尝试的回复正文／请求快照，同事务追加 `AssistantContextWithdrawn` 并更新投影；用户原始消息遵守独立删除范围 |
| 高 | 删除来源对话后的派生回复可能仍存在于其他会话；在途聊天只在提交时检查版本，网络请求未及时取消 | 清理跨会话及多轮传递依赖；运行观察撤销状态并取消 HTTP 请求，启动和上传前再校验上下文，迟到结果不能保存；原始请求版本变化后不能被旧运行当成一次新重试 |
| 中 | 120 秒时限不包含排队等待；超时被统一标为用户停止；排队显示「正在整理」 | 排队与执行合计受时限约束，排队时也观察撤销，超时持久化为 FAILED／TIMEOUT；分别显示排队、执行、停止和超时 |
| 中 | 记忆计划通过截取 JSON 接受正文前后的说明；仓库命令缺少引用上限及证据长度保护 | 仅接受完整 JSON 或完整 JSON 代码块，混入说明或多个文档整批失败；仓库也检查 MEMORY 绑定、引用数量／唯一性和证据长度 |
| 中 | 所有长词都拆成二元片段，英文问题容易命中无关词 | 仅连续汉字做二元字匹配，英文与数字按完整词匹配；保留中英文混合查询与既有字符预算 |
| 低 | 重复忘记已清空正文后会计算新指纹，与第一次的幂等键冲突 | 已终结的记忆再次执行终结操作直接返回，不追加冲突事件 |

旧版本已存在的忘记／失效记录，在本次应用恢复时补清理遗留派生正文。不重新执行模型、文件加载或任务调度。来源消息的撤销事件同时作为完成标记，后续恢复不再次清理用户明确重试产生的新回复。

回复撤销显示「相关记忆或来源已移除，旧回复已清理」。用户原文不会因为忘记一个事实而被整个删除；需要删除原文时使用删除对话。一次回复依赖被撤销内容时，保守地移除整条回复，保留未受影响会话。

## 验证

验证覆盖历史失败尝试、已完成回复、多轮传递依赖、跨会话来源删除、保留用户消息与无关回复、拒绝旧快照、重建一致性、已忘记记录的升级补清理，以及明确重试的新回复保留。

本机 HTTPS 假服务覆盖忘记时取消在途回复、取消排队整理不产生上传、超时持久化及只有主动重试才再次调用模型。纯测试覆盖完整 JSON 边界和中英文检索。

最终实际结果：

- `:app:assembleDebug` 与 `:app:testDebugUnitTest` 通过，32 项单元测试。
- `:app:connectedDebugAndroidTest` 选择 7 个相关测试类，在 Medium Phone API 36 与 Record Foldable API 36 模拟器各通过 45 项，共 90 次执行，零失败／跳过。测试类为 `PersonalAssistantTest`、`MemoryPlanningRepositoryTest`、`ConversationMigrationTest`、`ConversationRepositoryTest`、`ProcessingRepositoryTest`、`RecordingRepositoryTest`、`AssistantScreenTest`。
- `:app:lintDebug`、`ktlint`、`detekt` 全部通过。

APK：`app/build/outputs/apk/debug/app-debug.apk`。报告：`app/build/reports/tests/testDebugUnitTest`、`app/build/reports/androidTests/connected/debug`。

模拟器与假服务验证不代表真实模型记忆理解质量。真实模型评估、vivo 实体折叠验收、结构化主体／时间与跨新消息的同义忘记仍沿用第一版列明的未完成范围。

## 保留的边界

依赖清理以已记录的来源与引用为依据，无法识别未建立依赖的任意同义正文。跨新消息的语义重学、主体／谓词级抑制、多来源支持和自动替代尚未实现。此版仍须审核候选，不能把逐字证据匹配等同于事实正确。

整理仍使用保守的全局知识修订，无关记忆变化可能中断另一条整理任务。已发送给 provider 的内容无法通过本机清理撤回。
